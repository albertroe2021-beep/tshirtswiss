# TShirtSwiss Design Tokens

This document defines how the production-site visual system is converted into Elementor Free Global Styles and reusable section settings.

The source of truth is the visual reference library generated by `tools/reference-capture`. Values must be measured from the production pages rather than guessed.

## Token source

Use the following evidence in this order:

1. Computed styles from the production page
2. Desktop, tablet and mobile reference screenshots
3. Existing repository CSS and assets
4. Visual measurement where no explicit source value exists

Record extracted values in:

```text
elementor-kit/design-tokens/tokens.json
```

Null values mean that extraction or visual confirmation is still required. They must not be treated as defaults.

## Elementor mapping

### Global colours

Map the confirmed palette into Elementor Site Settings:

- Primary: main brand colour
- Secondary: supporting brand colour
- Text: default body text
- Accent: links, highlighted controls and emphasis
- Additional custom colours: surfaces, borders and status colours

Avoid hard-coded widget colours except where a component is intentionally unique.

### Global fonts

Create global typography styles for:

- Display
- H1
- H2
- H3
- H4
- Body Large
- Body
- Body Small
- Button
- Caption

Each style should record font family, size, weight, line height and letter spacing for desktop, tablet and mobile.

### Layout

The container system must define:

- Standard content width
- Wide content width
- Responsive horizontal page gutters
- Section top and bottom spacing
- Column and card gaps

Use Elementor Flexbox Containers. Avoid negative margins unless they are required to reproduce a measured overlap from the reference site.

### Buttons

Create three reusable button treatments:

- Primary
- Secondary
- Text or link-style action

For each treatment, record:

- Text typography
- Text and background colours
- Border width and colour
- Radius
- Horizontal and vertical padding
- Hover and focus states

### Cards and surfaces

Record reusable values for:

- Border colour
- Border radius
- Box shadow
- Internal padding
- Image aspect ratio
- Heading-to-body spacing

## Responsive baseline

The screenshot references use:

| Reference | Width | Height |
| --- | ---: | ---: |
| Desktop | 1440 px | 1000 px |
| Tablet | 768 px | 1024 px |
| Mobile | 390 px | 844 px |

Elementor breakpoint settings remain:

- Tablet: 1024 px and below
- Mobile: 767 px and below

The reference widths are comparison targets, not additional Elementor breakpoints.

## Acceptance rules

A token is considered confirmed only when:

1. It is supported by computed style data or repeatable visual measurement.
2. It works consistently across at least two representative pages.
3. Responsive values have been checked at all three reference widths.
4. It does not recreate the intentionally removed red announcement strip.

## Initial implementation order

1. Brand and neutral colours
2. Heading and body typography
3. Content widths and page gutters
4. Section spacing scale
5. Buttons
6. Card surfaces, radii and shadows
7. Header and footer-specific values

Once confirmed, the tokens should be applied to the Elementor global settings before page-level templates are assembled.
